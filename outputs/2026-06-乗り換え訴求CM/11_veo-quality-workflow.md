# Veo品質の動画をComfyUIで作るワークフロー設計

> 前提環境：MacBook Air M5 / 16GB。ComfyUI導入済み。
> 結論：**ルートA（API Nodes経由でVeo 3.1を直接呼ぶ）が本命**。ローカルモデルでVeo品質の再現は不可能。

---

## ルートA（本命）：ComfyUI API NodesでVeo 3.1を呼ぶ

ComfyUI公式の「API Nodes」機能を使うと、クラウドのフロンティアモデル（Google Veo、Kling、Hailuo等）を
ComfyUIのノードとしてワークフローに組み込める。**生成はクラウド側で走るのでMacのスペックは無関係**。
Flowが使えなくても、同じVeoモデルに別経路でアクセスできる。

### セットアップ

1. ComfyUIを最新版にアップデート（API Nodesは比較的新しい機能）
2. ComfyUI内でComfyUIアカウントにログイン（Settings → User）
3. クレジットを購入（プリペイド制・生成ごとに消費）

### ワークフロー構成（Image to Video）

```
[Load Image]               ← ComfyUI/SDXLで生成した各シーンの静止画
     │
[Google Veo 3.1 (Video)]   ← APIノード。プロンプト・秒数・縦横比を指定
     │                        ・9:16（縦型）対応
     │                        ・4〜8秒/クリップ
     │                        ・ネイティブ音声生成つき（環境音はVrew前に検討）
[Save Video]
```

- プロンプトは 07_flow-prompts.md がそのまま使える（Flowと同じVeo系モデルのため）
- 日本語テキスト固定の指定（②A・②B）もそのまま有効
- Veo 3.1は「最初と最後のフレーム指定」「参照画像」にも対応 → シーンのつなぎ制御に有効

### コスト目安（要最新確認）

| モデル | 8秒クリップあたり |
|---|---|
| Veo 3.1 Fast | 数百円程度 |
| Veo 3.1（標準） | 数百〜千円弱程度 |

> 本CMは実質6クリップ。全部Veo標準でも数千円規模。広告出稿費と比べれば誤差。

### 代替APIノード（同じ仕組みで使える比較対象）

| モデル | 特徴 |
|---|---|
| Kling 2.x | 人物・手の動きに強い。Veoよりやや安い |
| MiniMax Hailuo | コスパ良。モーション自然 |
| Wan 2.5（API版） | 音声つき。ローカル版とは別物の上位品質 |

## ルートB（参考）：ローカルモデルの品質上限

| 構成 | 品質 | 備考 |
|---|---|---|
| Wan 2.2 5B GGUF（16GB Macの上限） | Veoの6〜7割感 | 1クリップ数十分。物理挙動・細部でVeoに届かない |
| Wan 2.2 14B（要24GB+ GPU） | Veoの8割感 | そもそもM5 Airでは動かない |
| LTX-Video | 速度特化 | 品質はさらに下。下書き・動き確認用 |

ローカルで品質を底上げする後処理（やるなら）：
- RIFE等でフレーム補間（24→48fps相当の滑らかさ）
- 480p生成 → アップスケール（Topaz / Premiere内蔵）
- 軽いフィルムグレイン追加（AI感の緩和）

→ それでもVeo 3.1とは明確な差が残る。**商用CM品質が必要な本件ではルートA推奨**。

## クレジット節約運用（無料枠・少額運用向け）

> 原則：**「試行錯誤はローカル、本番1発だけVeo」**。Veoでリトライを回すと一瞬で枯れる。

### 二段構えワークフロー

```
【段階1：下書き＝ローカル（無料・無制限リトライ）】
[Load Image] → [LTX-Video I2V] → [Save Video]
  ・目的：プロンプトの動き・カメラワーク・尺の確定
  ・低解像度(480x832)・低品質でOK。「動きが意図通りか」だけ見る
  ・ここで何十回リトライしても0円

【段階2：本番＝Veo 3.1（確定プロンプトで1発）】
[Load Image] → [Veo 3.1] → [Save Video]
  ・段階1で確定したプロンプトをそのまま投入
  ・原則1シーン1生成。失敗時のみ1回だけ再試行
```

### Veo消費を減らす設定

| 設定 | 節約効果 |
|---|---|
| **Fastモードを使う** | 標準の半額以下。SNS広告の720p縦型なら品質差はほぼ出ない |
| **尺を4秒に絞る** | 8秒の半額。本CMの必要尺は1シーン4秒（①のみ5〜6秒） |
| **720pで生成** | 1080p不要。Reels/Shortsは720pで十分、必要なら後でアップスケール |
| 入力画像の質を上げる | I2Vの失敗の大半は入力画像起因。静止画段階で破綻ゼロの1枚を厳選 |

### リトライが必要になりやすいシーンの保険

| シーン | 保険 |
|---|---|
| ③A スタッフ（顔） | 先にローカルで表情の動き方を確認。Veoで失敗したら**Kling std**（安い・人物に強い）へ |
| ③B 車両 | 動きが単純なので**Hailuo / Kling std**で十分な可能性大。Veoを使わない選択肢 |
| ④A 空撮 | ここだけはVeoの価値が最大。**他シーンで節約してここに集中投下** |

### 予算ゼロで完走する場合の構成

全シーンをローカル（LTX下書き→Wan 2.2 5B GGUF本番）＋アップスケール＋フレーム補間で仕上げる。
品質はVeoに届かないが、②A・②B・④Bは元々動きが小さく差が出にくい。
→ まず1本完成させて出稿し、広告の反応が取れてからVeoでリメイクする判断もあり
（前作の教訓：完璧な素材より「冒頭テロップ0秒表示」の方がフック率に効く）。

## 本CMでの使い分け（プロデューサー推奨）

| シーン | 生成先 | 理由 |
|---|---|---|
| ②A 画面の明滅 | ローカル（LTX）でも可 | 動きが極小。クレジット節約 |
| ① 手元 / ②B タイピング | Veo 3.1 | 指の動きの自然さが必要 |
| ③A スタッフ / ③B 車両 | Veo 3.1 | 人物・車両モーションは品質差が最も出る |
| ④A 空撮 | Veo 3.1 | 広域モーションはローカル最弱・Veo最強領域 |
| ④B ロゴ＋QR | 生成不要 | Canva静止画のフェードで十分 |
